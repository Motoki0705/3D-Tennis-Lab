# Multicam 2D→3D System

This guide explains how to operate the `multicam_2d3d_system` package—our end-to-end pipeline that converts synchronized multi-camera footage into 3D ball/player trajectories. The document covers architecture, configuration, runtime flows, and extension points so you can adapt the system to new datasets or detectors.

## 1. Pipeline Overview

```mermaid
flowchart LR
    A(Videos) --> B[Detection]
    B --> C[Tracking]
    C --> D[Triangulation]
    D --> E[Temporal Smoothing]
    E --> F[Court Alignment]
    F --> G[Exports]
```

| Stage         | Responsibilities                                                                    | Key Modules                                             |
| ------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------- |
| Detection     | Run four pretrained detectors (players, ball, court, pose) on each camera stream.   | `src/detection/infer_*.py`, `configs/detection/*`       |
| Tracking      | Associate per-camera detections into lightweight tracks.                            | `src/detection/tracking.py`, `src/pipelines/track2d.py` |
| Triangulation | Fuse ball observations across cameras, smooth trajectories, map to the court frame. | `src/pipelines/twoD_to_threeD.py`, `src/geometry/*`     |
| Exports & Viz | Persist JSONL/Parquet outputs, enable downstream visualization.                     | `src/dataio/writers.py`, `configs/export/*.yaml`        |

The `src/pipelines/full.py` orchestration runs the stages sequentially; individual steps remain runnable in isolation for debugging.

## 2. Prerequisites

1. **Environment**
   - Python ≥ 3.10 with CUDA-enabled PyTorch (GPU compulsory for HRNet/RT-DETR/ViT-Pose).
   - Dependencies from `pyproject.toml` plus detector-specific requirements (`torchvision`, `transformers`, `opencv-python`, `numpy`, `hydra-core`).
2. **Model Weights**
   - Ball: HRNet/TrackNetV2 checkpoint (`.pth.tar`).
   - Players: RT-DETR Lightning checkpoint (`.ckpt`).
   - Court: DINO-FPN checkpoint.
   - Pose: ViT-Pose (HF Hub download is automatic; optional local cache).
     Update the corresponding paths in `configs/detection/*/*.yaml`.
3. **Dataset Layout**
   - Synchronized videos: `${workspace.root}/data/<camera_id>.mp4` (override via `data.frames.format`).
   - Calibration artifacts saved under `${workspace.outputs}/calibration/cameras.yaml` (generated by the calibration pipeline).

## 3. Configuration Anatomy

Configuration uses Hydra. The root file `configs/config.yaml` composes defaults from:

- `workspace/`: directories for inputs/outputs/cache.
- `data/`: dataset layout, camera IDs, annotation directories.
- `detection/`: per-detector overrides (weights, thresholds, GPU options).
- `triangulation/`: method and smoothing parameters.
- `export/`: output formats and target locations.

Example snippet (ball detector):

```yaml
detection:
  ball:
    _target_: hrnet_tracknetv2
    weights: ${workspace.root}/models/ball_tracking/hrnet/best_model.pth.tar
    device: cuda
    gpu_ids: [0]
```

Hydra overrides follow the usual syntax, e.g. `detection.player.device=cpu`.

## 4. Running the Pipeline

### 4.1 Full Pipeline

```bash
python -m multicam_2d3d_system.src.main pipeline=full \
    workspace.root=/data/matches \
    detection.ball.weights=/models/tracknet/best.pth.tar \
    detection.player.weights=/models/rtdetr/lightning.ckpt
```

Hydra will place outputs under `${workspace.outputs}` (defaults to `${workspace.root}/outputs`).

### 4.2 Individual Stages

Run detection only:

```bash
python -m multicam_2d3d_system.src.main pipeline=detect2d \
    data.cameras='[cam1,cam2]' data.frames.format=mp4
```

Run tracking on precomputed detections:

```bash
python -m multicam_2d3d_system.src.main pipeline=track2d \
    detection.tracker.method=simple_centroid \
    detection.tracker.max_frame_gap=3
```

Reconstruct 3D from existing detections:

```bash
python -m multicam_2d3d_system.src.main pipeline=triangulate3d \
    triangulation.smoothing.filter=kalman \
    triangulation.smoothing.kalman.smoothing_window=7
```

## 5. Stage Details

### 5.1 Detection (`src/pipelines/detect2d.py`)

- Players (`infer_player.py`): loads RT-DETR via `RTDetrLoadConfig`, filters for label 0, writes XYXY boxes.
- Ball (`infer_ball.py`): uses HRNet/TrackNetV2, handles temporal buffer, outputs point detections.
- Court (`infer_court.py`): DINO-FPN heatmaps -> argmax keypoints with score threshold, optional max count.
- Pose (`infer_pose.py`): ViT-Pose on top of player detections, stores per-keypoint scores.
- Output schema: list of `FrameDetections2D` dictionaries (camera_id, frame_idx, timestamp, detections, image_size).

**Common overrides**

| Key                                 | Meaning                           | Default |
| ----------------------------------- | --------------------------------- | ------- |
| `detection.ball.device`             | Torch device for HRNet.           | `cuda`  |
| `detection.player.score_threshold`  | RT-DETR post-process threshold.   | `0.5`   |
| `detection.court.max_keypoints`     | Cap on court keypoints per frame. | `null`  |
| `detection.pose.keypoint_threshold` | Minimum per-keypoint confidence.  | `0.3`   |

Outputs land in `${data.annotations.detections_dir}/detections.jsonl`.

### 5.2 Tracking (`src/pipelines/track2d.py`)

- Implements a centroid-based tracker (pending ByteTrack integration).
- Configurable per-class association radii, max frame gaps, and minimum track length.
- Results emit `tracks.jsonl` with per-camera track bundles.
- Extend by replacing `_run_simple_tracker` or wiring an external tracker inside `tracking.track_detections`.

### 5.3 Triangulation & Court Alignment (`src/pipelines/twoD_to_threeD.py`)

1. Buckets ball detections by `(frame_idx, timestamp)` across cameras.
2. Requires at least two calibrated cameras per frame.
3. Uses linear DLT triangulation (`geometry/triangulation.py`).
4. Applies moving-average smoothing (window from `triangulation.smoothing`).
5. Translates coordinates so the origin is at the mean camera position (`geometry/court_frame.py`).
6. Exports a reconstruction payload with provenance metadata (`writers.write_reconstruction`).

Resulting file: `${export.reconstruction.path}/reconstruction.parquet` (fallback to JSON if pandas is missing).

## 6. Outputs & File Structure

```
${workspace.outputs}/
├── hydra/                    # Hydra logs and configs per run
├── detections/detections.jsonl
├── tracks/tracks.jsonl
├── recon_3d/reconstruction.parquet
└── calibration/cameras.yaml  # expected input for triangulation
```

Each JSONL record matches `formats.FrameDetections2D` or `formats.CameraTracks`. Parquet rows contain ball trajectory frames with timestamps, coordinates, and camera provenance.

## 7. Extending the System

- **New detectors**: add a loader under `trained_models/`, register an inference wrapper in `src/detection`, and append a Hydra preset in `configs/detection/`.
- **Advanced tracking**: replace `_run_simple_tracker` with ByteTrack/DeepSORT while keeping the `formats.CameraTracks` contract.
- **Court alignment**: swap `court_frame.to_court_frame` with a homography-based solution once court keypoints are triangulated.
- **Temporal filtering**: implement Kalman smoothing inside `temporal_opt` using the process/measurement covariance placeholders already present in `configs/triangulation/smoothing/`.

## 8. Troubleshooting

| Symptom                                  | Likely Cause                                | Remedy                                                                               |
| ---------------------------------------- | ------------------------------------------- | ------------------------------------------------------------------------------------ |
| `ImportError` for trained-model loaders  | `trained_models` not on `PYTHONPATH`.       | Run from repo root or `pip install -e .`.                                            |
| Zero detections emitted                  | Detector weights missing or GPU mismatch.   | Verify `detection.*.weights` paths and set `device=cpu` only for RT-DETR/court/pose. |
| Triangulation warnings about calibration | Missing/invalid `calibration/cameras.yaml`. | Run calibration stage or update path via `workspace.outputs`.                        |
| `reconstruction.parquet` missing         | Requires pandas/pyarrow.                    | `pip install pandas pyarrow`, or inspect JSON fallback message.                      |
